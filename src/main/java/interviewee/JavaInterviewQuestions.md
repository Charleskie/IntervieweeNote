# Java 面试题清单

> 用法建议：先按模块过一遍，把不会讲清楚的题打标；二刷时重点补“原理 + 使用场景 + 常见坑 + 项目落地”。下面答案是面试口述版标准答案，适合先背框架，再针对薄弱模块扩写。

## 1. Java 基础

- [ ] Java 的基本数据类型有哪些？各自占多少字节？
  - 答案：8 种：`byte` 1、`short` 2、`int` 4、`long` 8、`float` 4、`double` 8、`char` 2、`boolean` 规范未固定大小，JVM 实现通常按 1 字节或 4 字节处理。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] `int` 和 `Integer` 的区别是什么？
  - 答案：`int` 是基本类型，存值；`Integer` 是包装类，存对象引用，可为 `null`，支持泛型和集合。`Integer` 有缓存，默认缓存 `-128` 到 `127`。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 自动装箱和自动拆箱是什么？有哪些隐藏坑？
  - 答案：装箱是基本类型转包装类，拆箱是包装类转基本类型。坑点是拆箱 `null` 会 NPE，包装类用 `==` 可能比较引用，频繁装拆箱有性能开销。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] `==` 和 `equals` 的区别是什么？
  - 答案：基本类型 `==` 比值，引用类型 `==` 比地址；`equals` 默认也是比地址，但很多类如 `String` 重写后比较内容。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 为什么重写 `equals` 时通常也要重写 `hashCode`？
  - 答案：哈希容器要求相等对象必须有相同 hash。只重写 `equals` 不重写 `hashCode` 会导致 `HashMap`、`HashSet` 查找和去重异常。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] `String`、`StringBuilder`、`StringBuffer` 的区别是什么？
  - 答案：`String` 不可变；`StringBuilder` 可变且非线程安全，性能好；`StringBuffer` 可变且方法加锁，线程安全但性能较低。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] `String` 为什么设计成不可变？
  - 答案：不可变有利于字符串常量池复用、hash 缓存、线程安全和安全性，避免字符串作为类名、路径、网络地址等关键参数时被修改。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 字符串常量池是什么？`new String("abc")` 创建了几个对象？
  - 答案：常量池保存字符串字面量以便复用。若池中没有 `"abc"`，会创建池中对象和堆上 `String` 对象共 2 个；若已有字面量，只创建堆上对象 1 个。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] `final` 可以修饰什么？分别有什么含义？
  - 答案：修饰类表示不可继承，修饰方法表示不可重写，修饰变量表示只能赋值一次；引用变量 final 后引用不可变，但对象内部状态仍可能变。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] `static` 的作用是什么？静态变量和实例变量有什么区别？
  - 答案：`static` 属于类级别，随类加载而存在；静态变量类共享一份，实例变量每个对象一份。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] Java 的值传递是什么意思？对象作为参数传递时发生了什么？
  - 答案：Java 只有值传递。对象参数传递的是引用值的拷贝，方法内能修改对象内容，但不能让调用方引用指向新对象。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 面向对象三大特性是什么？分别怎么理解？
  - 答案：封装隐藏实现暴露接口；继承复用和扩展父类能力；多态让父类引用指向子类对象，运行时根据实际类型调用方法。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 重载和重写的区别是什么？
  - 答案：重载发生在同一类，方法名相同参数不同，编译期确定；重写发生在父子类，签名相同，运行期根据实际对象动态绑定。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 抽象类和接口的区别是什么？
  - 答案：抽象类表达“是什么”，可有状态和构造方法，单继承；接口表达“能做什么”，多实现，更适合定义能力规范。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] Java 8 接口的默认方法和静态方法有什么作用？
  - 答案：默认方法允许接口新增方法而不破坏已有实现类；静态方法用于放接口相关工具逻辑，通过接口名调用。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 内部类、静态内部类、匿名内部类分别适合什么场景？
  - 答案：成员内部类依赖外部类实例；静态内部类不依赖外部实例，常用于 Builder/Holder；匿名内部类适合一次性实现接口或抽象类。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 深拷贝和浅拷贝的区别是什么？如何实现深拷贝？
  - 答案：浅拷贝只复制对象本身，引用字段仍共享；深拷贝会递归复制引用对象。可用拷贝构造、手动复制、序列化、JSON 转换等实现。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 序列化和反序列化是什么？`serialVersionUID` 有什么用？
  - 答案：序列化是对象转字节流，反序列化是字节流还原对象。`serialVersionUID` 用于版本校验，避免类结构变化导致不兼容。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] `transient` 关键字有什么作用？
  - 答案：被 `transient` 修饰的字段不参与 Java 默认序列化，反序列化后为默认值。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] Java 异常体系是怎样的？`Exception` 和 `Error` 的区别是什么？
  - 答案：顶层是 `Throwable`，下面是 `Error` 和 `Exception`。`Error` 多为 JVM 严重问题，不建议捕获；`Exception` 是程序可处理异常。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] 受检异常和非受检异常有什么区别？
  - 答案：受检异常继承 `Exception` 且非 `RuntimeException`，编译期必须处理；非受检异常继承 `RuntimeException`，通常表示编程错误。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] `try-catch-finally` 的执行顺序是什么？`finally` 一定会执行吗？
  - 答案：先执行 `try`，异常时进 `catch`，最后执行 `finally`。`finally` 通常会执行，但 `System.exit`、JVM 崩溃、进程被杀时不会执行。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。
- [ ] `try-with-resources` 的原理是什么？
  - 答案：资源实现 `AutoCloseable`，编译器自动生成 `finally` 调用 `close()`，可避免忘记关闭资源，并能处理 suppressed exception。 实际开发里还要关注空值处理、对象不可变性、装箱拆箱成本以及 API 设计是否清晰。

## 2. 集合框架

- [ ] Java 集合框架有哪些常见接口和实现类？
  - 答案：`Collection` 下有 `List`、`Set`、`Queue`；`Map` 独立。常见实现有 `ArrayList`、`LinkedList`、`HashSet`、`TreeSet`、`PriorityQueue`、`HashMap`、`TreeMap`、`ConcurrentHashMap`。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `ArrayList` 和 `LinkedList` 的区别是什么？
  - 答案：`ArrayList` 底层数组，随机访问快，尾部追加快；`LinkedList` 底层双向链表，按节点插删方便，但随机访问慢、内存开销大。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `ArrayList` 的扩容机制是什么？
  - 答案：首次添加时初始化容量，默认 10；容量不够时扩容为原来的 1.5 倍左右，再用 `Arrays.copyOf` 复制元素。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `HashMap` 的底层结构是什么？
  - 答案：JDK 8 是数组 + 链表 + 红黑树。数组定位桶，冲突先链表，链表过长且容量足够时树化。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `HashMap` put 流程是什么？
  - 答案：计算 hash，定位桶；桶空直接插入；key 相等则覆盖；冲突则链表或红黑树插入；超过阈值触发扩容。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `HashMap` 为什么长度通常是 2 的幂？
  - 答案：可用 `(n - 1) & hash` 替代取模，性能更好；配合 hash 扰动能让元素分布更均匀。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `HashMap` 什么时候树化？什么时候退化？
  - 答案：桶链表长度大于等于 8 且数组容量至少 64 时树化；树节点过少，通常小于等于 6 时退化为链表。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `HashMap` 在 JDK 1.7 和 JDK 1.8 中有什么区别？
  - 答案：1.7 是数组 + 链表，头插法，扩容并发下可能成环；1.8 增加红黑树，尾插法，降低极端冲突查询复杂度。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `HashMap` 为什么线程不安全？
  - 答案：并发 put、resize、覆盖时没有同步，可能导致数据丢失、覆盖异常、结构不一致和可见性问题。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `ConcurrentHashMap` 的底层原理是什么？
  - 答案：JDK 8 使用数组 + 链表 + 红黑树，读多为无锁 volatile，可用 CAS 初始化/插入，冲突时对桶头加 `synchronized`。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `Hashtable`、`HashMap`、`ConcurrentHashMap` 的区别是什么？
  - 答案：`Hashtable` 方法级同步，慢且不允许 null；`HashMap` 非线程安全，允许一个 null key；`ConcurrentHashMap` 线程安全且并发性能好，不允许 null。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `LinkedHashMap` 如何保证顺序？
  - 答案：在 `HashMap` 基础上维护双向链表，可按插入顺序或访问顺序遍历，常用于 LRU。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `TreeMap` 的底层结构是什么？如何排序？
  - 答案：底层红黑树，按 key 的自然顺序或构造时传入的 `Comparator` 排序，查找插入删除是 O(log n)。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `HashSet` 的底层实现是什么？
  - 答案：底层是 `HashMap`，元素作为 key，value 使用固定占位对象。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `Iterator` 遍历时删除元素为什么要用 `iterator.remove()`？
  - 答案：直接集合删除会导致 `modCount` 和迭代器期望值不一致，触发 fail-fast；`iterator.remove()` 会同步更新迭代器状态。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] 什么是 fail-fast 和 fail-safe？
  - 答案：fail-fast 检测并发修改后快速抛 `ConcurrentModificationException`；fail-safe 通常基于副本遍历，不抛异常但不一定看到最新数据。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `CopyOnWriteArrayList` 的原理和适用场景是什么？
  - 答案：写时复制新数组，读无锁。适合读多写少场景，不适合频繁写或大集合。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] `PriorityQueue` 的底层结构是什么？
  - 答案：底层是数组实现的二叉堆，默认小顶堆，可传比较器，入队出队 O(log n)，取堆顶 O(1)。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。
- [ ] 如何选择 `List`、`Set`、`Map` 的具体实现？
  - 答案：有序可重复用 `ArrayList`，频繁队列插删可用 `LinkedList`/`Deque`；去重用 `HashSet`，排序用 `TreeSet`；键值查找用 `HashMap`，并发用 `ConcurrentHashMap`，有序用 `LinkedHashMap`/`TreeMap`。 真正选型时通常还要同时考虑是否需要有序、是否允许重复、随机访问性能、内存开销和线程安全。

## 3. 泛型、反射、注解

- [ ] Java 泛型解决了什么问题？
  - 答案：泛型提供编译期类型检查，减少强制类型转换，提高代码复用性和类型安全。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。
- [ ] 泛型擦除是什么？为什么运行期拿不到泛型类型？
  - 答案：Java 泛型主要在编译期生效，编译后类型参数会被擦除为上界或 `Object`，所以运行期普通对象通常拿不到具体泛型。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。
- [ ] `List<?>`、`List<? extends T>`、`List<? super T>` 的区别是什么？
  - 答案：`?` 表示未知类型；`extends` 是上界，适合读取 T，不适合写入；`super` 是下界，适合写入 T，读取只能当 Object。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。
- [ ] 反射是什么？常见使用场景有哪些？
  - 答案：反射是在运行期获取类信息并操作字段、方法、构造器。常见于框架 IOC、ORM、注解扫描、动态代理和测试工具。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。
- [ ] 反射为什么慢？如何优化？
  - 答案：反射有访问检查、动态解析、无法充分内联等开销。可缓存 `Class/Method/Field`、关闭访问检查、使用 MethodHandle 或代码生成优化。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。
- [ ] 注解是什么？元注解有哪些？
  - 答案：注解是给代码附加元数据。常见元注解有 `@Target`、`@Retention`、`@Documented`、`@Inherited`、`@Repeatable`。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。
- [ ] 运行时注解如何读取？
  - 答案：注解需 `@Retention(RetentionPolicy.RUNTIME)`，运行期通过反射的 `getAnnotation`、`getDeclaredAnnotations` 等方法读取。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。
- [ ] 动态代理是什么？
  - 答案：动态代理是在运行期生成代理对象，在方法调用前后织入额外逻辑，常用于 AOP、事务、日志、RPC。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。
- [ ] JDK 动态代理和 CGLIB 动态代理的区别是什么？
  - 答案：JDK 代理基于接口和 `InvocationHandler`；CGLIB 基于继承生成子类，不能代理 final 类/方法。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。
- [ ] Java SPI 是什么？有哪些典型应用？
  - 答案：SPI 是服务发现机制，通过 `META-INF/services` 声明接口实现。典型应用有 JDBC Driver、Dubbo 扩展、日志门面实现加载。 这类能力虽然很灵活，但也要注意类型擦除、反射性能损耗以及框架使用边界。

## 4. Java 并发

- [ ] 进程和线程的区别是什么？
  - 答案：进程是资源分配单位，有独立地址空间；线程是 CPU 调度单位，共享进程资源，创建和切换成本更低。 回答并发题时最好顺带说明它主要解决可见性、原子性还是有序性问题，以及常见误用。
- [ ] 创建线程有哪些方式？

## 12. 消息队列

- [ ] 为什么要使用消息队列？
  - 答案：用于异步、削峰、解耦和流量缓冲，但会引入一致性、延迟、重复消费和运维复杂度。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] 消息队列如何削峰、解耦、异步？
  - 答案：生产者快速写入 MQ，消费者按能力消费；上下游只依赖消息协议；耗时操作异步执行。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] 消息丢失如何避免？
  - 答案：生产端确认、Broker 持久化和副本、消费者手动 ack、失败重试和死信队列。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] 重复消费如何解决？
  - 答案：业务端做幂等，如唯一键、去重表、状态机、Redis setnx、消息 ID 记录。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] 如何保证消息顺序？
  - 答案：同一业务 key 发到同一分区/队列，单消费者串行消费；全局顺序会牺牲并发。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] 死信队列是什么？
  - 答案：消息多次消费失败、过期或被拒绝后进入死信队列，便于排查、补偿和人工处理。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] 延迟消息如何实现？
  - 答案：可用延迟队列、时间轮、RocketMQ 延迟消息、RabbitMQ TTL + 死信、定时扫描任务。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] Kafka 的 Topic、Partition、Consumer Group 是什么？
  - 答案：Topic 是主题，Partition 是分区并行和顺序单位，Consumer Group 是消费者组，同组内分摊分区。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] Kafka 如何保证高吞吐？
  - 答案：顺序写磁盘、页缓存、零拷贝、批量发送、压缩、分区并行、拉模式消费。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] Kafka ISR、ACK、Offset 分别是什么？
  - 答案：ISR 是同步副本集合；ACK 控制生产确认级别；Offset 是消费者在分区中的消费位置。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。
- [ ] RocketMQ 的事务消息原理是什么？
  - 答案：先发送半消息，执行本地事务，再提交或回滚；Broker 可回查生产者确认事务状态。 工程上最关键的是可靠性、顺序性、幂等性和积压处理能力，而不是只会把消息发出去。

  - 答案：先构建 next/前缀表，匹配时失配就跳到最长相等前后缀位置，避免主串回退。 手写题除了思路本身，最好再补充时间复杂度、空间复杂度、边界条件和为什么这么选数据结构。
- [ ] 手写限流器：固定窗口、滑动窗口、令牌桶。
  - 答案：固定窗口按时间桶计数；滑动窗口维护多个小窗口或请求时间队列；令牌桶按速率生成令牌，请求消耗令牌。 手写题除了思路本身，最好再补充时间复杂度、空间复杂度、边界条件和为什么这么选数据结构。
- [ ] 手写本地缓存，考虑过期和并发。
  - 答案：用 `ConcurrentHashMap` 存 value、expireTime，可惰性删除 + 定时清理；容量控制可加 LRU；并发加载可用锁或 FutureTask 防击穿。 手写题除了思路本身，最好再补充时间复杂度、空间复杂度、边界条件和为什么这么选数据结构。
